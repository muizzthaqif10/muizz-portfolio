Most of what I work on day to day has no visual surface at all — it's mapping configs and payload transformations. Building this site was a chance to spend deliberate time on the other side of the stack, and it surfaced a few things that were easy to miss from the backend.

## Why Next.js and the App Router

I wanted server-rendered pages for SEO without giving up React for the interactive parts — the project filter, the command palette, the terminal widget. The App Router's split between Server and Client Components maps onto that cleanly: pages that are mostly content stay as Server Components and ship no extra JavaScript, and only the genuinely interactive pieces opt into being Client Components.

## Treating content like data

The thing that felt most natural, coming from integration work, was refusing to hardcode content inside components. Every project, skill, and experience entry lives in a typed data file:

```ts
export type Project = {
  slug: string;
  name: string;
  description: string;
  categories: ProjectCategory[];
  stack: string[];
  status: 'Live' | 'In Progress' | 'Case Study' | 'Archived' | 'Planned';
  // ...
};
```

That's not a frontend best practice I picked up from a tutorial — it's the same instinct as keeping a mapping spec separate from the engine that reads it. Change the data, not the code that renders it.

## The blog: MDX over a CMS

For a personal site with a handful of posts, a headless CMS is more infrastructure than the problem needs. Markdown files with frontmatter, read at build time, cover everything: title, tags, reading time, and a table of contents generated by scanning the raw markdown for headings before it's rendered.

### What I'd still change

The GitHub integration on the projects page falls back to static data gracefully when no username is configured, but I haven't wired up a real contact-form backend yet — that's sitting behind an environment variable, ready for whichever of Resend, Formspree, or a small Vercel Function I end up picking. Small, deliberate gaps like that are easier to leave visible than to fake.
